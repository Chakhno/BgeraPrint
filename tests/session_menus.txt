#!menus
# The menu interface, played from a file.
#
# The #!menus line on top matters: after the first command these lines are
# ANSWERS TO MENUS, not typed commands, so the test that checks every line
# is a real command skips this file, and a test that actually plays it and
# looks at the model that comes out checks it instead.
#
#     python -m tests.play tests/session_menus.txt --fresh
#
# There is no keyboard when a file is playing, so the menus ask for a typed
# answer instead: a number, or the name of the choice. Everything else is
# identical, which is what makes this worth having -- it proves the menus
# reach the same places the arrow keys do.
#
# Sizes are typed here for the same reason: you cannot hold an arrow key
# down in a text file, so the app switches to typed numbers by itself
# whenever it is being fed from one.
#
# Note where there is NO line below: when only one answer is possible the
# app just takes it rather than asking. Sitting the braille on the plate
# does not ask which plate, because there is only one.
#
# Listen to the output. Every line should make sense read aloud, and nothing
# should say "I do not understand" or "I do not know that one".

# Switch into the menus from the typing side.
menu
